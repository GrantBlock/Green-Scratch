# API Contract

How the Concepts Vault, the Concepts Hub, the Assistant and the tests talk to each other. The records are defined in `data-model.md`; this file is the rules and the routes. The code lives in `packages/contract` and is the source of truth: if this page and the code disagree, the code wins and this page is regenerated.

Status: **C0, first version.** The mock server in `packages/core` (`npm run mock`) implements every route here, running the same business logic as the real server.

---

## Main Prompt: Conventions

#### Additional Prompt: Basics

- **Base path:** `/api/v1` for the Vault. The Hub serves its own routes under `/hub`.
- **Format:** JSON in and out. Field names are camelCase. Record types are named as in `data-model.md`.
- **Ids:** opaque strings set by the server. Registry numbers (`BC-Q-26021`) are separate and issued only by the server; a client can never send an `id`, a `number`, `version`, `createdAt`, `updatedAt` or `type`.
- **Money:** whole cents as integers (`4850000` is $48,500.00). Never a decimal.
- **Dates:** `YYYY-MM-DD` for dates, ISO 8601 with offset for times.
- **Archive, never delete.** Records have an `archived` flag. Lists hide archived records unless `archived=true`.

#### Additional Prompt: Reading

- `GET /{resource}` lists. Filter by any field (`status=Open`, `projectId=...`), search with `q`, page with `limit` and `cursor`. Response: `{ "items": [...], "nextCursor": null }`.
- `GET /{resource}/{id}` returns one record.
- **Computed fields** are added on read and never stored: a project has `completeness` (0 to 100), an invoice has `displayStatus` (which can be `Overdue`) and `daysLate`.
- `GET /today` returns the Today screen (new leads, follow-ups due, overdue invoices, visits in the next 7 days, missing documents).

#### Additional Prompt: Writing

- `POST /{resource}` creates; `PATCH /{resource}/{id}` updates.
- **Concurrency:** every record has a `version`. A PATCH must send the version it last saw; a stale one returns `conflict`.
- **State changes** go through the action routes below, never by patching `status`, so the allowed transitions and side effects always run.
- **Released documents are locked.** Changing one means a new revision (`POST /documents/{id}/revisions`); the old one becomes Superseded.
- **Every write** appends an audit event. Writes that change dates require a reason, which is stored on the item's updates.

#### Additional Prompt: Errors

Status code, then `{ "error": { "code", "message", "fields"? } }`. Messages are written for a person.

| Code | Status | Meaning |
|---|---|---|
| `validation_failed` | 400 | Bad input; `fields` names each problem |
| `not_found` | 404 | No such record, route or link |
| `conflict` | 409 | Stale version, a number already used, or a duplicate action |
| `locked` | 409 | A Released document was edited directly |
| `invalid_transition` | 409 | That state change is not allowed (see `states.ts`) |
| `unauthorized` | 401 | Not signed in to the Vault |
| `forbidden` | 403 / 405 | The link or method does not allow that |
| `rate_limited` | 429 | Too many requests, or the Assistant's monthly budget is used up |
| `unavailable` | 503 | A service the request needs (such as the Assistant's model) cannot be reached right now |
| `expired`, `revoked` | 410 | A customer link has expired or been revoked |

#### Additional Prompt: Access

- **Vault:** one user. Sign-in is handled in front of the app; every Vault route requires it.
- **Hub:** no Vault session. Customer routes use a share token in the path. The server stores only a hash of the token; the token is shown once, when the link is created.
- **Hub boundary:** the Hub has no database or file-storage binding. It reaches the Vault only through `VaultPublicApi` (in `packages/contract/src/hub.ts`): submit a contact, list the Library, read a share page, read a permitted document, accept an upload. Nothing else. A customer link exposes only documents that are **Released and Customer-shared** and belong to the link's project; Temp, Inbox and Claude folders can never be shared. Customers never see Registry numbers.

#### Additional Prompt: Change process

1. Change the record or route in `packages/contract` and `spec/data-model.md` in one small commit.
2. Update `fixtures/data.ts` so the fixtures still validate.
3. Run `npm test` and `npm run typecheck` in `packages/contract`; run `npm run docs` to regenerate the table below.
4. Only then change the Vault, the Hub or the UI.
