# Reset: one approach, built outward from the live website

**Why this exists.** Most of the files used so far came from earlier AI conversations, and it is not clear which decisions in them were deliberate. This document stops treating them as requirements. It sorts them by evidence and proposes one unified approach.

## 1. The only constant

The live site at blockconceptsllc.com (repo `GrantBlock/calm-swag`):

- Static HTML/CSS/JS, generated by `build/build.ps1`, deployed on Cloudflare (`wrangler.jsonc` publishes `public/`). No backend, no database.
- Its spec states the positioning chain: specialty automation → one accountable source → Engineering, Sourcing, Services → solutions as proof.
- It says it is "a positioning site, not a portal", and that Concepts Hub releases later as a separate system.
- Its design system (dark theme, Overpass, Steel Blue) and copy rules are the brand.
- Its contact is phone and email only. The contact form is built in but disabled.

Everything else below is measured against that.

## 3. The unified approach

> **Update:** the addresses are now decided. The private side is `vault.blockconceptsllc.com` and the customer-accessible side (public tools and customer project pages) is `hub.blockconceptsllc.com`. The diagram below predates this; see `docs/WORKFLOW.md` section 6.

One product with three layers, one brand, one number sequence and one data model. The website stays the front door.

```
blockconceptsllc.com         PUBLIC WEBSITE  (live, static)
        |  contact form posts a lead
        v
app.blockconceptsllc.com     CONCEPTS VAULT (private)  (Grant only)
        |   Leads -> Opportunities -> Projects -> Documents
        |   Accounts, Knowledge base, Library of templates
        |   Claude assistant over all of it
        |
        +--> customer project pages (expiring links: download PDFs, upload requested files)
        ^
agent email (own subdomain)  inbound newsletters, invoices, replies
```

- **Layer 1, public website.** Unchanged except for one thing: the contact form goes live and sends a lead to the Vault. Public tools (a document library, a builder) come later, only if the work shows they are worth it.
- **Layer 2, customer delivery.** A minimal branded page per project, reached by an expiring link: released PDFs to download, and upload slots for requested documents. No customer accounts.
- **Layer 3, Concepts Vault.** Where the day-to-day lives. It replaces monday.com first, then takes over document collection and follow-ups, then the knowledge base, then the assistant.

**Shared across all three:** the design system, `BC` numbering, the data model in `spec/data-model.md`, and an audit log.

**Repo plan.** Keep `calm-swag` as the live website, untouched except for the contact form. Build the Vault in this repo (`Green-Scratch`) as its own Cloudflare project on a subdomain. The design system is the one shared source. This keeps the live site safe while the Vault is built.

## 4. How to build it without repeating the problem

The earlier approach was spec-first from other people's documents. This one is workflow-first from yours.

1. **Describe the real workflow.** What you open each morning, what you track per opportunity, what you do when a deal is won, where documents go, what you chase. Short and rough is fine.
2. **Replace monday.com first with the thinnest version.** Enter your 30 opportunities and 6 projects. Use it for two weeks. Write down what is missing.
3. **Add one layer at a time:** documents and checklist, customer links, financial tracking, agent email, knowledge base, assistant. Each starts from what the previous one taught you.
4. **Specs are written after the workflow is clear, one slice at a time,** and kept short.
